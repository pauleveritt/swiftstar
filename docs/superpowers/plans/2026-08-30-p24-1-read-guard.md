# P24.1 read-guard (`don't-re-read`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the app's own session answer an unchanged file re-read with
"unchanged since turn N" instead of re-serving the whole file into KV, killing
the measured 1809 re-read tax (37.5% of Σsuffix).
**Architecture:** A pure `ReadGuard` store+verdict in `SwiftStarKit` (fast-tier
tested), wired into the existing `HostToolExecutor.readResult` (the one seam —
no new executor, no wire change, no engine change, no recapture). The executor
hashes every read (the file read is ~1 ms vs the 5.9–15.6 s prefill sync it
avoids), consults the guard, and either serves the whole file (recording
hash/mtime/turn) or returns "unchanged since turn N". `more` is attributed to
the last-read path. Write/edit invalidates. Scope: the app session only; the
pool worker's existing hash cache is untouched (P24.1b).
**Tech Stack:** Swift, `SwiftStarKit` + `SwiftStarAppKit` + `SwiftStar`, the
existing `HostToolExecutor`/`ToolCallbackResponder`/`PoolWireParser` machinery,
CryptoKit (SHA256, already used by the pool cache). No engine, no model, no
network.
**Spec:**
[`2026-08-30-p24-1-read-guard-design.md`](../specs/2026-08-30-p24-1-read-guard-design.md)
(design decisions D1–D8; the plan argues from the spec). Before-measurement:
[`2026-08-30-p24-1-read-guard-before-measurement.md`](../research/2026-08-30-p24-1-read-guard-before-measurement.md).

## Global Constraints

- **Zero engine work.** No `external/ds4` change, no wire field, no tool name,
  no golden recapture (spec D7). This plan touches only Swift sources, tests,
  and one CLI verb.
- **Hash is authoritative** (D1): every read reads the file and hashes; the
  verdict compares hashes. mtime is recorded alongside, never trusted to skip
  the read.
- **App session only** (D8): `Policy.pool`'s `readCache` hash cache is
  byte-for-byte unchanged; all new behavior is gated behind `Policy.readGuard`,
  true only for `.app`.
- **Red-first** (BRIEF.md rule 2): every changed/new test must be shown failing
  before the implementation lands; a refusal case gets a sibling success case
  (rule 4).
- **Worktree-safe by key** (D3): guard entries are keyed by the
  confinement-resolved real path; the store is per-executor-instance; the app
  executor resets on session start/restart.
- **The paired-bill guardrail** (spec rule 4): the win is claimed only after
  `swiftstar-analyze diff` on a live session at close (Task 4), never from
  self-reported savings.

## Task 1: `ReadGuard` — pure store + verdict (SwiftStarKit)

**Files:**
- Create: `Sources/SwiftStarKit/ReadGuard.swift`
- Test: `Tests/SwiftStarKitTests/ReadGuardTests.swift`

**Interfaces:**
- Produces (consumed by Task 2 and the Task 4 replay):

```swift
public struct ReadGuardEntry: Equatable, Sendable {
    public let hash: String
    public let mtime: Double
    public let turn: Int
}

public enum ReadVerdict: Equatable, Sendable {
    case serve
    case unchanged(sinceTurn: Int)
}

public struct ReadGuard: Sendable {
    public private(set) var entries: [String: ReadGuardEntry]
    public init()
    public func verdict(path: String, hash: String) -> ReadVerdict
    public mutating func record(path: String, hash: String, mtime: Double, turn: Int)
    public mutating func invalidate(path: String)
    public mutating func reset()
}
```

`verdict`: `.unchanged(sinceTurn: e.turn)` iff `entries[path]?.hash == hash`,
else `.serve`. Pure — no I/O, no model.

- [ ] **Step 1: Write the failing test**

Create `Tests/SwiftStarKitTests/ReadGuardTests.swift`, a `@Suite struct
ReadGuardTests` with `import Testing` + `import SwiftStarKit`. Tests (name —
the assertion it pins):

- `firstReadServes` — `ReadGuard().verdict(path:hash:)` on an empty store is `.serve`.
- `equalHashReReadIsUnchangedWithRecordedTurn` — after `record(path: "a", hash: "h", mtime: 1, turn: 3)`, `verdict(path: "a", hash: "h")` is `.unchanged(sinceTurn: 3)`.
- `changedHashServes` — same record, `verdict(path: "a", hash: "h2")` is `.serve`.
- `unchangedMessageUsesRecordedTurnNotCallerTurn` — record at `turn: 3`; verdict carries `sinceTurn: 3` even though the guard itself is given no "current turn" (the executor supplies it; this pins that the message names when the file was last served).
- `invalidateForcesServe` — record, `invalidate`, verdict is `.serve`.
- `resetClearsAllEntries` — record two paths, `reset()`, both verdicts are `.serve`.
- `recordUpserts` — record "a" twice with different hashes, verdict matches the latest.

```bash

```

Expected: FAIL — "no such module" / type not found (file doesn't exist yet).

`entries` defaults to `[:]`; `verdict` is non-mutating; `record` upserts;
`invalidate` removes; `reset` removes all. Doc comment states the D1 contract:
hash is authoritative, mtime is recorded provenance, the caller does all I/O.

- [ ] **Step 4: Run it to verify it passes**

Using the file's existing `makeWorkspace`/`request`/`param` helpers (note:
`request(name, params, workspace:, path: nil)` yields `resolvedPath: nil`, which
the guard path treats as the `more` no-path case only when name is `more`):

- `guardShortCircuitNamesTheRecordedTurn` — `executor.setTurn(3)`, read, re-read →
  `"unchanged since turn 3"`.
- `guardServesFreshWhenContentChanges` — read, rewrite the file, read →
  full new text (not "unchanged").
- `guardServesOnFirstReadPerPath` — read a.txt then b.txt → both serve full text.
- `moreContinuesTheLastReadPath` — read a.txt (serve), then `request("more", [], workspace: ws, path: nil)` → `"unchanged since turn 0"` (attributed to a.txt).
- `moreWithNoPriorReadErrors` — `more` with no prior read → `!ok` and `text.contains("could not read")`.
- `writeInvalidatesTheGuardEntry` — read a.txt, `edit` it (returns `mutations: [path]`), re-read → serves the edited text, not "unchanged".
- `guardIsScopedPerWorkspaceRoot` (spec test 3 — the worktree requirement): two temp workspaces `wsA`/`wsB`, both with `a.txt` = "hello"; read in each with its own executor; overwrite `wsA/a.txt` = "changed"; `wsA` re-read serves "changed", `wsB` re-read is still `"unchanged since turn 0"` (disjoint keys, D3).
- `resetReadGuardClearsEntriesAndTurn` — `setTurn(5)`, read, re-read → "unchanged since turn 5"; `resetReadGuard()`; re-read → serves full text.

- [ ] **Step 5: Implement the executor changes**

In `Sources/SwiftStarAppKit/HostToolExecutor.swift`:

1. `Policy` (:46): add `public var readGuard: Bool`; `.app` (:66) sets
   `readGuard: true` (keeps `readCache: false`); `.pool` (:75) sets
   `readGuard: false` (keeps `readCache: true`). The two static constructors
   are the only construction sites (verify with
   `grep -rn "Policy(" Sources/ Tests/`).
2. Instance state (:84): add `private var readGuard = ReadGuard()`,
   `private var currentTurn = 0`, `private var lastReadPath: String?` (all
   guarded by the existing `lock`).
3. `readResult` (:160): first branch

```swift
if policy.readGuard { return readResultGuard(request) }
```

   (the existing `readCache`/plain branches stay untouched for `.pool`).
4. New `readResultGuard` (private): for `more`, `path = lastReadPath` and nil →
   `ToolExecutionResult(ok: false, text: "error: could not read")`; otherwise
   `path = HostToolConfinement.realPath(request)` and nil → the existing
   "path is outside the workspace grant" refusal. Then: read bytes → on failure
   the existing "could not read \(path)"; `hash = SHA256(bytes)`;
   `mtime = (try? FileManager.default.attributesOfItem(atPath: path)[.modificationDate] as? Date)?.timeIntervalSince1970 ?? 0`. Under `lock`:
   `switch readGuard.verdict(path: path, hash: hash)` — `.unchanged(let turn)` →
   `ToolExecutionResult(ok: true, text: "unchanged since turn \(turn)")`;
   `.serve` → `readGuard.record(path: path, hash: hash, mtime: mtime, turn: currentTurn)`, `lastReadPath = path`, return the full text.
5. `writeResult` (:215) and `editResult` (:233): on success (before returning),
   `lock.withLock { readGuard.invalidate(path) }`.
6. New `setTurn(_ n: Int)` and `resetReadGuard()` (both `lock.withLock`).

- [ ] **Step 1: Extend `rereads` with a `--guard` replay mode**

In `Sources/swiftstar-analyze/main.swift`: `rereads [--guard] [DIR|--latest]`.
When `--guard` is present (argv[2] == "--guard", dir at argv[3] or `--latest`),
after printing the existing per-worker counts, replay each worker's
`readRequests` through a fresh `ReadGuard` and print the short-circuit summary:

- For each worker, maintain `var guardStore = ReadGuard()`; for each read in
  order: resolve the path against the current working directory (the capture's
  workspace), read the bytes; on read failure skip the read (file gone today);
  `hash = SHA256(data)` (reuse the same hex-sha helper as the executor — add a
  tiny local `sha256Hex(Data) -> String` if none exists in the analyze target);
  `switch guardStore.verdict(path:hash:)` — `.unchanged` → `shortCircuits += 1`,
  `.serve` → `guardStore.record(path:hash:mtime: 0, turn: 0)`.
- Print per worker: `"guard replay: X of Y read/more calls short-circuited"`
  and per path with `count > 1`: `"  %3d  %@  -> %d short-circuit"`.

The replay is a *simulation of within-session stability* (the capture had zero
mutations), so using today's content for every read of a path is correct: the
guard's verdict depends only on relative stability, not on today's bytes
matching 2026-08-27's (spec Cycle 4).
