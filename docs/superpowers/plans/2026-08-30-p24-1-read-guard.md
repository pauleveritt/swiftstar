# P24.1 read-guard (`don't re-read`) implementation plan

This plan was superseded before implementation. It is retained as the
decision trail; the close record below points to the replacement design and
the later measurement.

## Goal

Test whether a host-side hash/mtime guard can prevent redundant reads without
withholding bytes after partial delivery or compaction.

## Planned work

- Add the pure `ReadGuard` store and verdict in
  `Sources/SwiftStarKit/ReadGuard.swift`, with refusal and success tests in
  `Tests/SwiftStarKitTests/ReadGuardTests.swift`.
- Wire the guard through `HostToolExecutor.readResult` and the app turn
  ordinal, with tests covering writes, repeated reads, and compaction.
- Add a live falsifier and record its result in research before deciding
  whether to keep the guard.

## Decision boundary

The design required an honest coverage model, compaction invalidation, an
escape hatch, and a measurement capable of returning a non-"before" result.
It was re-scoped to window-honoring reads before this plan was executed.

## Result

Superseded on 2026-08-30. No read-guard implementation from this plan shipped.
The host instead learned to honor the engine's read windows and continuation
format in `Sources/SwiftStarKit/ReadWindow.swift:1` and
`Sources/SwiftStarAppKit/HostToolExecutor.swift:1`. The post-windowing
re-decision then retired both this guard and the pool `readCache`; see
`docs/superpowers/specs/2026-08-30-p24-1-window-honoring-reads-design.md` and
`docs/superpowers/specs/2026-08-30-p24-2-read-guard-redecision-design.md`.
