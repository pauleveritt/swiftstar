## Problem

A build phase (`swiftstar-agenttest/main.swift`, ~line 671) that fails its
`validationCommand` (e.g. an import check) aborts the whole run before
`commitBack()`. `RepairLoop` exists and fixes this exact defect class 4/4 live,
but it's only wired after the *final* acceptance grade (worker 2) — never
reachable from a phase failure. 5 of 6 P15 build-run failures were one-line
content defects at a phase boundary (wrong import, wrong module, mount path
outside grant) that `RepairLoop` would plausibly fix.

This is unfinished P12 scope, not new work — P12's charter was host-owned
"budgets, permissions, validation, **and recovery**"; P12.4 only wired the
last of those at the acceptance boundary.

## Three coupled changes (not independently mergeable)

1. **Don't abort on phase validation failure — repair it instead.** The abort
   exists on purpose (finding C17: stops a broken tree chaining into the next
   phase), so replace it with a `RepairLoop.run` call, don't delete it.
2. **Bridge the evidence types.** `RepairLoop.run`'s `grade` closure expects a
   `GradeResult` (exit + full pytest output); a phase failure produces a
   `ValidationResult` (exit + combined stdout/stderr, now captured as of
   `05a4fcc`). Needs a conversion or a generalized grade closure.
3. **Change what "passing" means mid-roadmap.** `RepairLoop`'s grade closure
   currently runs the full acceptance suite, which can't pass on phase 1 code
   against phase 3 tests. A phase-level call needs to grade against the
   phase's own `validationCommand`, not the acceptance suite.

## Also true, worth knowing before designing

- `RepairLoop` exits immediately on *any* receipt, including `validationFailed`
  — a repair that itself fails the import check gets no second attempt. Decide
  whether phase-level recovery needs that changed too, or whether one repair
  attempt per phase failure is the right scope.
- Two workers exist (`WorkerId(1)` build, `WorkerId(2)` repair) — phase-level
  repair should probably reuse worker 2's pattern, not worker 1's session.
