# P11 smoke gate: the n=2 pool multiplexes, routes, and exits cleanly

> **Superseded as a live finding** by [`2026-08-25-local-model-agency.md`](2026-08-25-local-model-agency.md). Retained as the evidence record for the n=2 smoke-gate PASS run and the live Metal-concurrency segfault it caught during worker init.

**Status:** smoke-gate evidence (correctness, not measurement). The full
measurement gate — the 4.2x context-curve envelope — is the overnight run.
**Date:** 2026-08-23

The smoke gate answers the question GLM 5.2 flagged as "the everything-else-moot
check": does the n=2 pool actually multiplex two sessions on one engine, route
prompts by worker id, tag events correctly, and exit without crashing or
deadlocking — against the real engine and weights.

## Command

```bash
bash Tools/p11-smoke-gate.sh
# (SWIFTSTAR_MODEL / SMOKE_CTX / SMOKE_SETTLE override the defaults)
```

It spawns `ds4-agent -c 16384 --metal --non-interactive --json-events
--host-tools --subagent-pool 2`, then after load + both workers' init sends a
bare prompt (→ worker 0) and a `PoolPrompt` (→ worker 1), then closes stdin and
checks the exit code and the wire.

## Result (all PASS, exit rc=0)

- `hello` carries the `"pool"` cap and `"worker":0`.
- worker 0's turn completes (events tagged `"worker":0`).
- worker 1's turn completes (events tagged `"worker":1`); its turn-end ready:
  `{"t":"ready",...,"stop_reason":"eos","generated":23,"ctx_used":1041,...,"worker":1}`.
- clean exit, `rc=0` (no crash, no deadlock).

## What this run is NOT

It does not measure the context-curve win. A 2-worker run on a tiny prompt
produces no meaningful overhead ratio — that is the full gate's job (131k deep
baseline vs 8×16k workers, all five perturbation arms), scheduled overnight.

## A real bug this smoke gate caught

The first live run segfaulted (`Metal command-buffer assertion`) because **two
worker threads prefilled the system prompt concurrently** during init, racing on
the shared engine's Metal device. Fixed by serializing worker init under the
same pool mutex that serializes turns (`external/ds4` commit `d351b40`). This is
exactly the class of "N sessions sharing one engine" hazard the pool mutex
exists for — and it was only observable live, not in the C unit tests.
